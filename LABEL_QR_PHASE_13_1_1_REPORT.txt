BRICKMISSING 8
PHASE 13.1.1 - LABEL STUDIO LARGE SELECTION / HTTP 400 FIX
Stand: 2026-08-29

1. ROOT CAUSE
=============

Das Label Studio serialisierte das vollständige Formular einschließlich jeder
ausgewählten LegoSet-UUID in die URL. Bei großen Sammlungen überschritt die HTTP-
Request-Line dadurch das Serverlimit (Production: 6481 > 4094 Byte), bevor Django die
Anfrage überhaupt verarbeiten konnte.

Der Setbild-Schalter war nicht selbst defekt. Seine Änderung startete denselben langen
Preview-GET. Nach HTTP 400 blieb wegen des vorhandenen Fehler-/Race-Schutzes die alte
Preview im DOM, sodass das Bild scheinbar nicht reagierte.


2. ALTER REQUEST-FLOW
=====================

Der bisherige Browserablauf war:

  FormData
  -> URLSearchParams
  -> alle item=<UUID>-Werte im Querystring
  -> GET /organisation/etiketten-qr/?...

Dies galt sowohl für partielle Live-Previews als auch für den vollständigen
Studio-Refresh beim label_type-Wechsel. Anschließend schrieb history.replaceState()
dieselbe vollständige URL einschließlich sämtlicher UUIDs in die Browser-History.


3. NEUER REQUEST-FLOW
=====================

Der neue Browserablauf ist:

  FormData einschließlich csrfmiddlewaretoken und vollständiger Auswahl
  -> POST-Body
  -> POST /organisation/etiketten-qr/

Die Request-URL bleibt konstant und enthält keine ausgewählten Set-UUIDs. Partielle
Previews senden weiterhin X-Requested-With: XMLHttpRequest. Beim Typwechsel wird
ebenfalls POST verwendet, aber vollständiges HTML angefordert; daraus wird wie bisher
nur [data-label-studio] ersetzt.

AbortController, Sequence/Stale-Response-Schutz, 180-ms-Debounce, Retry-Fehlerzustand,
Loading State, aria-busy, Print Readiness und Empty State bleiben erhalten.


4. GET/POST-SEMANTIK
===================

label_studio akzeptiert jetzt explizit GET und POST:

- GET: normale Navigation und initiale vollständige Studio-Seite;
- POST mit X-Requested-With: partielle Live Preview;
- POST ohne X-Requested-With: vollständige Seite für den Studio-Komponentenwechsel.

Die View verwendet eine gemeinsame Eingabeschicht:

  params = request.POST if request.method == "POST" else request.GET

Alle Studiofelder werden konsistent daraus gelesen: type, item, images, qr_target, q,
start, checked_text, checked_count und selection.

Die übrigen echten read-only Ressourcen bleiben GET-only und liefern bei POST 405:

- label_set_qr
- label_preview
- label_print_css
- label_qr


5. CSRF
=======

Das Studioformular verwendet method=post, eine explizite label_studio-Action und
{% csrf_token %}. JavaScript sendet FormData direkt als POST-Body. Dadurch wird der
vorhandene csrfmiddlewaretoken ohne csrf_exempt und ohne Secret in der URL übertragen.

Ein Test mit Client(enforce_csrf_checks=True) bestätigt:

- POST ohne CSRF-Cookie/Token -> HTTP 403;
- POST mit dem von der GET-Seite gesetzten Token -> HTTP 200.

Djangos CsrfViewMiddleware bleibt unverändert aktiv.


6. GROSSE SETAUSWAHL
====================

Der Regressionstest erstellt 111 eigene ausgewählte Sets. Der äquivalente alte
Querystring ist nachweislich länger als 4094 Byte. Dieselbe Auswahl wird nun per AJAX-
POST mit HTTP 200 verarbeitet; alle 111 Sets erscheinen in den erzeugten Slots.

Ausgewählte UUIDs werden defensiv validiert. Ungültige Werte werden ignoriert und
führen nicht zu einem UUID-Parsing-500. Anschließend filtert das bestehende
owner=request.user-Queryset die Auswahl. Nur tatsächlich eigene Set-IDs werden wieder
in den Kontext übernommen.

Bei einem Typwechsel unter aktivem Suchfilter werden ausgewählte, gerade nicht
sichtbare Sets als owner-geprüfte versteckte Formfelder erhalten. Damit geht die
Auswahl beim vollständigen Komponenten-Refresh nicht verloren. "Alle abwählen"
entfernt sowohl sichtbare Checkbox-Auswahl als auch diese erhaltenen Felder.


7. BROWSER-URL / HISTORY
========================

history.replaceState verwendet nicht mehr den vollständigen FormData-Querystring.
Die kurze URL darf nur folgende UI-Felder enthalten:

- type
- q (für die History auf 100 Zeichen begrenzt)
- start
- images
- qr_target
- checked_text
- checked_count

Nicht aufgenommen werden item, selection oder csrfmiddlewaretoken. Hunderte UUIDs und
CSRF-Daten gelangen somit weder in die Adresszeile noch in die History. Nach einem
echten Reload verwendet die GET-Seite wie vorgesehen wieder die normale
Default-Auswahl.


8. SETBILD-SCHALTER
===================

Der Schalter verwendet jetzt denselben erfolgreichen POST-Preview-Flow wie alle
anderen Live Controls.

Getestet mit der großen Auswahl:

- images=0 -> HTTP 200, keine label-set-image-Elemente;
- reales aktiviertes Checkbox-FormData mit images=0 und images=1 -> HTTP 200 und ein
  Setbild für jedes der 111 Sets;
- erneutes Umschalten ist nicht mehr von einer langen Request-Line abhängig.

Django QueryDict.get() verwendet den letzten Formwert, sodass das bestehende Hidden-
0-plus-Checkbox-1-Muster weiterhin korrekt arbeitet.


9. OWNER-ISOLATION
==================

Owner-Isolation wurde nicht gelockert:

- Ausgangsqueryset bleibt owner=request.user und deleted_at__isnull=True;
- eine gültige fremde Set-UUID im POST wird nicht ausgewählt oder gerendert;
- fremder Setname und Daten erscheinen nicht in der Antwort;
- nur IDs aus dem owner-gefilterten Ergebnis werden für weitere Studio-Refreshes
  erhalten;
- ungültige IDs werden ohne Datenbankfehler verworfen.

Loginpflicht, Image Proxy und die vorhandenen QR-Zielprüfungen bleiben unverändert.
