1. Zusammenfassung
------------------
Die bestehende Set-Liste besitzt jetzt den Mehrfachfilter „Fehlende Farben“.
Ein Set wird aufgenommen, sobald mindestens eine aktuell fehlende normale oder
Minifiguren-Allokation exakt eine der ausgewählten Farben besitzt. Mehrere
Farben gelten innerhalb des Filters als ODER; Suche, Themenwelt,
Vollständigkeit und weitere unabhängige Filter bleiben UND-verknüpft.

2. Bestehende Architektur und Mengenlogik
-----------------------------------------
Die Set-Liste verwendet bereits apps.catalog.services.with_set_completeness().
Diese fachliche Wahrheit basiert direkt auf den autoritativen Allokationen:

- SetInventoryItem: required_quantity / owned_quantity
- MinifigurePart: quantity / owned_quantity
- nur aktive Sets
- nur normale, benötigte Zeilen
- Spare-Zeilen sind ausgeschlossen
- Eigentümer und Set werden exakt eingegrenzt

Die gemeinsamen Allokations-QuerySets wurden in
_authoritative_set_allocation_querysets() gebündelt. Sowohl
with_set_completeness() als auch der neue Filter verwenden diese Quelle. Es
wurde keine Part.owned_quantity-basierte Parallelberechnung eingeführt. Die
bestehende Owned-Quantity-/Allocation-Synchronisation, Reconciliation, der
LEGO-Export und die Fehlteile-Logik wurden nicht abgeschwächt oder umgebaut.

3. Genaue Filtersemantik
------------------------
Query-Parameter: missing_color (wiederholt für Mehrfachauswahl)

- Eine Farbe: EXISTS einer autoritativ fehlenden Allokation dieser Farbe.
- Mehrere Farben: color_name IN (Auswahl), also ODER-Semantik.
- Andere fehlende Farben desselben Sets beeinflussen den Treffer nicht.
- Vollständig vorhandene Allokationen treffen nicht.
- Vollständige Sets treffen nicht.
- Mehrere passende Allokationen erzeugen wegen EXISTS kein doppeltes Set.
- Der Filter ist mit Suche, Themenwelt und Vollständigkeit UND-verknüpft.
- Sortierung und Pagination behalten die wiederholten Query-Parameter über
  das bestehende Django-querystring-Template bei.
- Entfernen/Zurücksetzen erfolgt über die bestehende „Alle Farben anzeigen“-Aktion.

4. Farblogik
------------
Die UI verwendet unverändert die zentrale Farblogik in
apps/catalog/colors.py (grouped_colors/color_category) und die bestehende
Komponente templates/components/color_multiselect.html. Damit gelten dieselben
Gruppen und Mappings, insbesondere Lime/Green, Light Nougat/Brown, Trans sowie
Metallic/Pearl/Flat. Gefiltert wird konservativ nach dem exakten gespeicherten
color_name; die Gruppen verändern keine Identität und führen keine zweite
Farbklassifikation ein.

5. Query- und Performance-Ansatz
--------------------------------
Die Set-Filterung erfolgt datenbankseitig mit zwei korrelierten EXISTS-
Unterabfragen (normale SetInventoryItem-Allokationen und MinifigurePart-
Allokationen). Dadurch entstehen weder Join-Duplikate noch Part-für-Part-
Queries. Die Auswertung des gefilterten Set-QuerySets benötigt unabhängig von
der Set-Anzahl eine Abfrage; dies ist mit assertNumQueries(1) regressionsgetestet.
Die angebotenen fehlenden Farben werden in zwei zusätzlich begrenzten,
benutzerbezogenen Mengenabfragen ermittelt. Es gibt kein N+1-Verhalten.

6. UI / UX
-----------
Der Filter nutzt das bestehende Midnight-Violet-Mehrfachauswahl-Design und die
vorhandene JavaScript-Funktion für Auswahlzähler, Schließen und Zurücksetzen.
Die ausgewählte Anzahl ist sichtbar. Ausgewählte Query-Werte bleiben auch dann
in der Auswahl sichtbar, wenn sie derzeit keinen Treffer mehr besitzen. Das
bestehende responsive Zwei-/Einspaltenverhalten bleibt erhalten; das breite
Desktop-Raster wurde um genau das neue Filterfeld erweitert.

3. Prüfen, dass Sets mit mindestens einem fehlenden schwarzen Teil erscheinen.
4. Prüfen, dass ein Set auch erscheint, wenn zusätzlich andere Farben fehlen.

6. Prüfen, dass OR-Logik gilt.
7. Set ohne Black/Red-Fehlteil darf nicht erscheinen.
8. Vollständiges Set darf nicht erscheinen.
9. Kombination mit Suche, Sortierung und anderen Filtern testen.

11. Pagination und Erhalt beider Farbparameter prüfen.
