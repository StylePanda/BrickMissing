BRICKMISSING 8 – PHASE 7.2 ABSCHLUSSBERICHT
Stand: 2026-08-14

1. ZUSAMMENFASSUNG

Phase 7.2 stellt den Set-Autofill wieder her, ergänzt benutzerbezogene
Rebrickable-Zugangsdaten, Theme-/Subtheme-Vorschläge, eine zugängliche
Fehlteile-Lightbox, das gemeinsame Formularlayout für Teile und eine klarere
Aktionshierarchie im Django Admin.

Behobene Hauptprobleme:
- Das neue Set-Template hatte keinen Autofill-Hook mehr.
- Der alte Rebrickable-Service verwendete einen globalen Server-Key.
- Theme und Subtheme waren unassistierte Textfelder.
- Fehlteilebilder waren nicht vergrößerbar.
- Das Teileformular nutzte noch das generische Alt-Layout.
- Admin-Aktionsicons und Primär-/Sekundäraktionen waren nicht sauber ausgerichtet.

Bekannte Einschränkungen:
- Kein echter Live-Aufruf von Rebrickable wurde ausgeführt. Alle API-Tests sind gemockt.
- Im Projekt ist keine Playwright-/Browser-Test-Suite konfiguriert.

2. SET HINZUFÜGEN

Das Formular verwendet weiterhin die gruppierte sectioned-form-Struktur mit
zweispaltigem Desktop- und einspaltigem Mobile-Layout.

Theme und Subtheme sind editierbare HTML-Comboboxen über TextInput + datalist:
- bestehende Werte können ausgewählt werden;
- Tippen filtert browserseitig die Vorschläge;
- neue Werte bleiben zulässig und speicherbar;
- Neu/Gebraucht, Vollständigkeit und Aufbaustatus bleiben ChoiceFields.

Das Formular enthält nun einen CSP-sicheren Backend-Lookup-Hook, einen sichtbaren
Lade-/Fehlerstatus und einen Einrichtungslink, falls kein API-Key vorhanden ist.

3. REBRICKABLE-INTEGRATION

Verwendete API: Rebrickable API v3.
Basis: https://rebrickable.com/api/v3/lego/

Für Phase 7.2 verwendete GET-Endpunkte:
- colors/?page_size=1 – ungefährlicher Verbindungstest
- sets/{set_num}/ – Set-Metadaten
- themes/{theme_id}/ – Theme und optional Parent-Theme
- sets/{set_num}/minifigs/?page_size=1 – Minifigurenanzahl über count

Bestehende Synchronisationsfunktionen nutzen zusätzlich:
- sets/{set_num}/parts/?page_size=1000
- sets/{set_num}/minifigs/?page_size=1000
- minifigs/{minifig_num}/parts/?page_size=1000
- sets/{set_num}/instructions/

Authentifizierung:
Authorization: key <persönlicher API-Key>

Der API-Key wird nicht als URL-Parameter übertragen. Externe Requests laufen
ausschließlich serverseitig. Timeout: 20 Sekunden. Redirects werden nicht verfolgt;
Antwortgröße und JSON-Struktur werden validiert.

Behandelte Fehler:
- fehlender Key
- ungültiger Key / HTTP 401 oder 403
- HTTP 404
- HTTP 429 / Rate Limit
- Timeout, DNS- und Netzwerkfehler
- HTTP 5xx
- ungültiges oder zu großes JSON

4. REBRICKABLE ACCOUNT SETTINGS

Im Profil existiert der neue Bereich „Rebrickable“ mit:
- API-Key speichern oder ändern
- Verbindungsstatus
- Verbindung testen
- Verbindung entfernen
- Hilfetext und Link zur offiziellen Rebrickable-API-Seite

Der Key wird als Passwortfeld eingegeben und nach dem Speichern nie erneut im HTML
ausgegeben. Speichern, Testen und Entfernen sind POST- und CSRF-geschützt.

Die Speicherung erfolgt verschlüsselt im benutzerbezogenen Feld
User.rebrickable_api_key_encrypted. Verwendet wird die bestehende Fernet-basierte
Secret-Verschlüsselung des Account-Systems. Querysets und Views arbeiten immer mit
request.user; fremde Keys werden weder gelesen noch ausgeliefert.

Audit-Events enthalten nur die Aktionen key_saved beziehungsweise key_removed,
niemals Key, Token oder Klartext. JSON-/CSV-Exporte enthalten keine Account-Secrets.
Der bisherige globale REBRICKABLE_API_KEY wurde aus Settings und .env.example entfernt.

5. SET-AUTOFILL

Ursache der Regression:
Beim neuen Phase-7-Setformular wurden der frühere JavaScript-Hook und ein geeigneter
Lookup-Endpunkt nicht übernommen. Der vorhandene Service war außerdem ausschließlich
für nachträgliche Synchronisation mit einem globalen API-Key gebaut.

Neue Abfolge:
1. Eingabe der Setnummer
2. 600 ms Debounce
3. vorherigen Request über AbortController abbrechen
4. GET an den angemeldeten BrickMissing-Lookup-Endpunkt
5. serverseitiger Rebrickable-Aufruf mit dem persönlichen Key
6. validierte JSON-Antwort
7. Übernahme noch nicht manuell bearbeiteter Felder

Mapping Rebrickable -> BrickMissing:
- set_num -> set_number
- name -> name
- year -> year
- num_parts -> total_parts
- set_img_url -> image_url
- Theme.name / Parent-Theme.name -> theme und subtheme
- Minifiguren-Response count -> minifigures

Setnummern ohne Variantensuffix werden deterministisch auf „-1“ normalisiert:
60069 wird zu 60069-1. Bereits konkrete Varianten wie 60069-2 bleiben erhalten.
Es wird keine beliebige Variante aus mehreren Suchtreffern ausgewählt.

Bei unbekanntem Set, Rate Limit oder API-Ausfall bleibt das Formular vollständig
manuell nutzbar. Bereits manuell bearbeitete beziehungsweise vorbefüllte Werte werden
nicht blind überschrieben.

6. THEMENWELTEN

Datenquelle sind ausschließlich aktive und gelöschte Sets des angemeldeten Benutzers.
Theme und Subtheme werden getrennt aus LegoSet.theme beziehungsweise LegoSet.subtheme
gelesen. Leere Werte werden ignoriert, Whitespace wird normalisiert, Duplikate werden
case-insensitiv zusammengeführt und alphabetisch sortiert.

Die datalist-Combobox erlaubt vorhandene Vorschläge und freie neue Eingaben. Ein von
Rebrickable geliefertes Theme wird wie jeder manuelle Wert in das Theme-Feld übernommen
und erweitert nach dem Speichern automatisch die lokale Vorschlagsliste.

Subthemes werden als kontoweite Vorschlagsliste angeboten. Eine harte Abhängigkeit vom
Theme wurde nicht eingeführt, weil das lokale Datenmodell keine verbindliche
Theme-/Subtheme-Referenztabelle besitzt.

7. FEHLTEILE

Vorhandene Teilebilder sind semantische Buttons. Sie öffnen ein natives dialog-Element
mit dunklem Overlay, großem responsivem Bild, Titel/Element-ID und sichtbarem
Schließen-Button.

Accessibility:
- aria-label am Trigger
- aria-labelledby und dialog-Semantik
- Fokus wandert zum Schließen-Button
- Fokus kehrt nach dem Schließen zum Trigger zurück
- ESC schließt über das native Dialogverhalten
- Klick auf den Overlay-Bereich schließt
- Tastaturbedienung ohne Inline-JavaScript

Ohne Bild wird ausschließlich der stabile „Kein Bild“-Placeholder angezeigt; ein
kaputter Lightbox-Trigger wird nicht erzeugt.
