1. STATUS / MENGEN / PERSISTENZ
Ursache:
- Die spezialisierten Mengen-, Status-, Bulk-, Minifiguren- und Set-Inventar-Endpunkte speichern
  bereits atomar und konsistent.
- Das allgemeine PartForm/update_part konnte jedoch status=found/received/installed zusammen mit
  owned_quantity=0 speichern. Legacy-Importdaten konnten denselben widersprüchlichen Zustand tragen.
- Das erklärt "gefunden + Bestand 0" als vorhandenen Datenzustand; es ist kein Beleg für einen
  ausschließlich lokalen UI-Updatefehler.

Behebung:
- Terminale Verfügbarkeitsstatus normalisieren owned_quantity auf quantity.
- Vollständig vorhandene Teile können nicht als missing gespeichert werden.
- Bestehende POST-Endpunkte bleiben atomar, owner-scoped und laden in Regressionstests erneut aus DB.
- Keine automatische Korrektur der 171 Production-Datensätze.

2. SET-VOLLSTÄNDIGKEIT
Ursache:
- LegoSet.completeness enthält einen manuellen/Legacy-Snapshot.
- Detailansicht, Minifiguren und Labels nutzten bereits apps.catalog.services.set_completeness;
  der gespeicherte Snapshot wurde bei Mengenänderungen nicht zuverlässig synchronisiert.

Behebung:
- Eine zentrale Regel in set_completeness:
  missing == 0 -> Vollständig; missing > 0 -> Unvollständig.
- Auch Sets ohne relevante Positionen ergeben gemäß dieser Regel Vollständig.
- Das Setformular bietet keinen manuellen Vollständigkeitsstatus mehr an.
- Neuer Command reconcile_set_completeness:
  Standard ist read-only Dry-run, Ausgabe mit Setnummer/sicherer ID und Mengen.
  Nur die ausdrückliche Option --apply schreibt die berechneten Werte.

Dry-run:
  python manage.py reconcile_set_completeness

Explizites Anwenden (NICHT ausgeführt):
  python manage.py reconcile_set_completeness --apply

3. ETIKETTEN & QR-CODES
Ursache:
- Alle vier Vorlagen und die Option "Setbilder anzeigen" waren im aktuellen Code vorhanden.
- labels.js reduzierte HTTP-, Server- und Antwortstrukturfehler auf eine generische Meldung.
- Eine HTTP-200-Antwort ohne erwartetes Preview-Fragment wurde still akzeptiert.

Behebung:
- HTTP-Status und eine begrenzte, bereinigte Servermeldung werden sichtbar ausgegeben.
- Fehlende Preview-/Studio-Fragmente werden als konkrete Fehler erkannt.
- Fehler werden ohne innerHTML und CSP-konform in den DOM geschrieben und in console.error protokolliert.
- Retry, Live-Preview, Startpositionen, QR-Ziele, HERMA-Maße und Bild an/aus bleiben erhalten.
- Tests decken vier Vorlagen, Partial-Preview, leere/mehrfache Auswahl, Startpositionen,
  Bild an/aus, QR-Ziele und Eigentümergrenzen ab.
